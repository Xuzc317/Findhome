## 总览

| 数据源 | 状态 | 需要登录 | 详情页 | 时间字段语义 | 本次实测入库 |
|--------|------|---------|--------|-------------|-------------|
| 豆瓣租房 | ✅ 列表可用（有风控） | 否 | 可用（未风控时） | 最后回应时间 | **59 条**（北京） |
| 贝壳找房 | ✅ 列表可用（有验证码风控） | 否（列表） | ❌ 验证码保护 | 维护时间 | **17 条**（深圳） |
| 闲鱼 | 🔐 需登录 | 是 | ❌ | — | 0（平台要求登录） |
| 小红书 | 🔐 需登录 | 是 | ❌ | — | 0（平台要求登录） |

状态含义：

- ✅ **可用**：真实请求后能解析出结构化房源
- 🔐 **需登录**：平台明确要求登录（未配置 Cookie 时不会发起无效请求）
- 🚫 **被拦截**：触发验证码/风控中间页，按边界不绕过
- ❌ **不可用**：接口下线或页面结构不可解析
- ⚪ **空结果**：请求成功但该条件下确实没有数据（**与"被拦截"严格区分**）

## 一致性校验结果

| 数据源 | 方法 | 结果 |
|--------|------|------|
| 贝壳 | 同一房源编号两次独立抓取比对（08:53 vs 10:07） | ✅ **14/14 标题与价格完全一致** |
| 贝壳 | 线上重新抓取列表页，与库内记录逐条比对 | ✅ **5/5 一致**（`python verify_consistency.py --source beike`） |
| 豆瓣 | 重新抓取帖子页比对标题 | ⚠️ **无法比对**：请求被平台风控中间页拦截（见下文） |

豆瓣无法自动复验的原因：该 IP 在 08:11 成功采集后进入风控期，此后所有
`group/*/discussion` 与 `group/topic/*` 请求都返回"请点击下方按钮继续浏览"中间页，

- 已入库的 59 条数据来自 08:11 的真实页面解析（可用 `source_url` 在浏览器人工核对）
- 配置本人 `DOUBAN_COOKIE` 后可重新采集并自动完成一致性比对

## 1. 豆瓣租房（douban）

**结论：可用，但平台有频率风控；触发后需等待冷却或配置本人 Cookie。**

### 已验证事实

| 项目 | 实测结果 |
|------|---------|
| 列表页 | `https://www.douban.com/group/{group_id}/discussion` |
| 未登录访问 | 可访问（未被风控时） |
| 实际入库 | 2026-10-04 08:11 单页采集 **59 条**北京真实房源 |
| 页面表结构 | 4 列：`td.title` 标题 / `td`(无 class) 作者 / `td.r-count` 回应数 / `td.time` 时间 |
| 风控表现 | HTTP 200 但返回"请点击下方按钮继续浏览"中间页；或 HTTP 429 |

### 关键修正（原实现有误）

- 原实现把 `td[1]` 当作时间列 —— 实际那是**作者**，导致所有房源发布时间都变成"当前时间"。
- 时间列实际是 `td.time`，格式 `10-04 05:59`（无年份），已补全跨年处理。
- 时间语义是**最后回应时间**，不是独立发布时间；已在 `raw_data.time_semantics` 中标注，
  不把它伪装成"发布时间"。

### 小组 ID 状态

| 城市 | 小组 ID | 状态 |
|------|---------|------|
| 北京 | `26926`, `279962` | ✅ 已验证（实采 59 条） |
| 上海 | `shanghaizufang` | ⚠️ 待验证 |
| 深圳 | `106955` | ⚠️ 待验证 |
| 广州 | `gzsh` | ⚠️ 待验证 |
| 杭州 | `hzsh` | ⚠️ 待验证 |
| 成都 | `cdzufang` | ⚠️ 待验证 |

待验证的城市可在未被风控时用 `python crawl.py douban --city 上海` 逐个确认；
若 ID 失效，用 `--group <真实小组ID>` 覆盖。

## 2. 贝壳找房（beike）

**结论：列表页无需登录即可采集，且已验证解析稳定；详情页被验证码保护，按边界不抓取。**

### 已验证事实

| 项目 | 实测结果 |
|------|---------|
| 列表页 | `https://{city}.zu.ke.com/zufang/`，无需 Cookie |
| 单页条数 | **30 条/页**（`div.content__list--item`），实际入库 17 条（去重后） |
| 解析字段 | 标题、价格、行政区、商圈、小区、面积、朝向、户型、楼层、标签、封面图、房源编号 |
| 已验证城市 | 深圳、杭州、西安、重庆、苏州、长沙（均返回 30 条） |
| 房源编号 | 卡片属性 `data-house_code`，如 `SZ2216761791667503104` |
| 详情页 | ❌ 返回 1123~6340 字节的**验证码/登录中间页** |
| 风控节奏 | 实测"冷却约 10 分钟后单次请求成功，紧接着再次请求即被拦截" |

### 关键修正（原实现有误）

- 原实现**没有 Cookie 就直接 `return []`**，把公开可用的数据源变成了"不可用"。
- 原实现用 `params={"pn": page}` 分页 —— 贝壳实际分页路径是 `/zufang/pg2/`。
- 原实现标签选择器 `i.content__item__tag` 匹配不到，实际 class 形如
  `content__item__tag--decoration`。
- 原实现把列表页的"X天前维护"当作发布时间 —— 已改为独立字段 `last_active_time`，
  `publish_time` 留空（不猜测）。
- 面积/户型/朝向最初全部解析失败：`get_text(" ")` 会在嵌套标签间插入空格，
  形成 `南山区 - 南头 - 小区 / 89.00㎡ / 南`，导致正则不匹配。已归一化 `/` 两侧空白，
  并增加单字段兜底（仍只读平台自己的文案）。

### 边界说明

详情页返回验证码页，**不尝试绕过**。因此：

- `DETAIL_AVAILABLE = False`，不抓详情，不做无谓试探
- 列表页给出的 `source_url` 在用户浏览器中可正常打开
- 房源经纬度因此缺失，地图不展示（**不伪造坐标**）

## 3. 闲鱼（xianyu）

**结论：需要用户本人登录态（Cookie）。未配置时明确上报 `needs_login`。**

### 已验证事实

| 探测目标 | 实测结果 |
|---------|---------|
| 旧接口 `s.2.taobao.com/list/` | ❌ 302 到 `deny_pc.html`（封禁页） |
| `www.goofish.com/search` | ❌ 纯客户端渲染 SPA，HTML 内 0 条商品数据 |
| `h5api.m.goofish.com/.../idlemtopsearch.pc.search` | 🔐 `ret: ["RGV587_ERROR::SM::哎哟喂,被挤爆啦,请稍后重试!"]`，`data.url` 指向 `passport.goofish.com/mini_login.htm` |

### 边界说明

该接口除登录态外还需要 `x-sign` 等由页面 JS 生成的签名参数。
**不进行签名逆向**（属于绕过访问控制）。因此 Adapter 的行为是：

1. 未配置 `XIANYU_COOKIE` → 直接返回 `needs_login`，**不发起无效请求**
2. 已配置 Cookie → 尝试请求，并把平台返回的**原文**上报（成功则解析，失败则说明原因）

## 4. 小红书（xiaohongshu）

**结论：需要用户本人登录态（Cookie）。未配置时明确上报 `needs_login`，不做无限试探。**

### 已验证事实

| 探测目标 | 实测结果 |
|---------|---------|
| `GET /api/sns/web/v1/search/notes` | ❌ HTTP 500 `create invoker failed` |
| `POST /api/sns/web/v1/search/notes` | 🔐 HTTP 200 `{"code":-101,"success":false,"msg":"无登录信息，或登录信息为空"}` |
| `/search_result` 页面 HTML | ❌ 客户端渲染，`__INITIAL_STATE__` 仅含全局配置，**0 条笔记链接** |
| `/explore` 首页 | ⚠️ 有 93 条推荐流链接，但属于个性化推荐、不可按城市检索，**不用于采集** |

### 边界说明

小红书 Web 接口要求 `x-s` / `x-t` 签名头（由页面 JS 生成）。
**不做签名逆向**。Adapter 行为与闲鱼一致：未配置 Cookie 直接上报 `needs_login`；
配置后尝试请求并如实上报平台返回。

## 如何提供登录 Cookie（仅用户本人浏览器）

1. 在**自己的浏览器**中正常登录对应平台（可用扫码/短信验证码）
2. 打开开发者工具 → Network → 任意请求 → 复制 `Cookie` 请求头
3. 写入项目根目录的 `.env`（**该文件已被 .gitignore 忽略，不会进入 Git**）：

```env
# 只使用本人浏览器登录后的 Cookie，不要写入代码/文档/日志
XIANYU_COOKIE=
XIAOHONGSHU_COOKIE=
DOUBAN_COOKIE=
BEIKE_COOKIE=
```

4. 重新执行 `python crawl.py health` 查看状态变化

> 本项目不要求、也不接受用户密码；不实现验证码识别或签名逆向。

## 复现命令

```bash
cd HouseSearch-local-v1
source .venv/bin/activate

# 0) 离线解析测试（65+ 项，无需联网、不触发风控）
python tests/test_parsers.py

# 1) 真实探针：确认每个平台当前的真实状态（含原因）
python crawl.py health

# 2) 豆瓣（优先级最高，未风控时可用）
python crawl.py douban --city 北京 --pages 1
python crawl.py douban --city 北京 --pages 1 --with-detail 5   # 额外抓前 5 条详情

# 3) 贝壳（列表页公开；--rent-type 1 合租 / 3 整租）
python crawl.py beike --city 深圳
python crawl.py beike --city 深圳 --rent-type 1

# 4) 闲鱼 / 小红书（需先在 .env 配置 Cookie）
python crawl.py xianyu --city 上海
python crawl.py xiaohongshu --city 上海

# 5) 验收记录：导出每个来源的真实房源（标题/价格/时间/链接/抓取时间）
python verify_sources.py --write docs/acceptance.md

# 6) 线上一致性校验（与平台当前页面比对）
python verify_consistency.py --limit 5

# 7) 接口契约 + 筛选闭环自检
python verify_api.py
```

## 风控与礼节

- 各 Adapter 有最小请求间隔（豆瓣 5s、贝壳 8s、闲鱼/小红书 6~8s），可通过
  `.env` 的 `CRAWL_INTERVAL` 调大，不建议调小。
- 实测连续快速请求贝壳会触发验证码，豆瓣会触发 429 或中间页。
  触发后应停止请求等待冷却，而不是加大频率。
- 本项目的原则：**被拦截就如实上报 `blocked`，绝不把"被拦截"呈现为"没有房源"**。
